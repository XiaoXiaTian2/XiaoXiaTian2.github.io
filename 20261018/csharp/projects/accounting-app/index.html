AccountingApp 是整個課程中規模最大的綜合專案：一個可以記帳、附上收據圖片、在表格中修改刪除，並做分組統計與圖表分析的 WinForms 記帳本。這篇整理它的架構，以及我在裡面用到的設計模式、LINQ 與反射。

# 專案簡介

功能分成四個畫面，由上方的 Navbar 切換：

畫面功能
記一筆輸入日期、金額、類別、細項、對象、付款方式，並上傳兩張圖片
記帳本依日期區間查詢，在 DataGridView 中直接修改（ComboBox 欄位）、雙擊看大圖、刪除
帳戶分析依類型／對象／付款方式分組、勾選篩選條件，統計金額
圖表分析同樣的分組與篩選，產生折線圖、圓餅圖或堆疊長條圖
  • 平台：.NET Framework 4.8、WinForms
  • NuGet 套件： AutoMapper 10.0.0
  • 參考： System.Windows.Forms.DataVisualization （圖表）、自己寫的 CSV 類別庫（ ..\CSV\bin\Debug\CSV.dll ）
  • 資料儲存：每天一個資料夾，裡面放 data/data.csv 與 img/ 圖片
  • Repo：https://github.com/XiaoXiaTian2/AccountingApp

# 6. SingletonForm 與 Navbar：用反射做頁面切換

Navbar 本身則用 Assembly.GetExecutingAssembly().DefinedTypes 掃描整個 Assembly，找出「繼承 Form 且含有 navbar1 欄位」的類別，自動產生按鈕。因為 Form 的類別名稱就是中文頁名，按鈕文字直接用 type.Name ；新增頁面時只要在 Form 上拖一個 Navbar，選單就會自動出現。

# 待改進

  1. clone 後無法編譯： AccountingApp.csproj 參考 ..\CSV\bin\Debug\CSV.dll ，這個 CSV 類別庫不在 repo 裡， RecordRepository 、 DataRepository 與幾個 View 都 using CSV; 。別人 clone 下來會缺少參考而編譯失敗。修正方向：把 CSV 專案一起放進 solution 用專案參考，或打包成 NuGet。
  2. 資料路徑寫死在本機磁碟： Models/Repositories/RecordRepository.cs 與 Presenters/AddAccountPresenter.cs 都寫死 baseFolder = @"E:\csharp_course\accounting" （ Utility/AcoountingTargetHelper.cs 也有一份）。沒有 E 槽或資料夾結構不同的電腦上，存檔與讀檔都會失敗。可以改成讀 App.config ，或預設放在 AppDomain.CurrentDomain.BaseDirectory 底下。
  3. DebounceClick 的 static timer 只會執行第一次的 callback： Utility/FormExtension.cs 的 timer 是 static 欄位，只有在 timer == null 時才用當下的 callback 建立 System.Threading.Timer ，之後的呼叫只做 timer.Change(due, -1) 。也就是說，之後傳入不同的 callback（或不同的 Form）都不會生效，到期時仍執行第一次綁定的那個；兩個多載還共用同一個 timer。目前只有 記帳本.button1_Click 一處呼叫，而且 lambda 每次都讀同一個 Form 的控制項，所以還看不出症狀，但只要第二個地方使用就會出錯。修正方向：以 Form 或按鈕為 key 各自保存 timer，或每次都更新要執行的 callback。
  4. 刪除後重繪會因圖片路徑為 null 而丟例外：刪除流程用 Img1 當識別 key（ RecordRepository.DeleteAccount 以 rec.Img1 != recordDAO.Img1 過濾， EditRecords 也用 Img1 找目標）。因為新增時圖片檔名用 Guid.NewGuid() ，目前 key 不會重複，但識別依賴檔案路徑本身就很脆弱。更直接的問題在 Views/記帳本.cs ： OnDeleteAccount 把 DTO 轉回 RecordModel 時漏掉了 Img1 、 Img2 ，接著 dataGridView1_CellDoubleClick 呼叫 ReRender() ，對每一列執行 ImageSet(rows[i].Cells["Img1"].Value?.ToString()) ，傳入 null 給 File.ReadAllBytes 會丟出例外。也就是刪除後只要還有剩下的資料，重繪就會失敗。修正方向：替記錄加上獨立的 Id 欄位，並在 OnDeleteAccount 補上圖片路徑。

# 小結

AccountingApp 是我第一次把 MVP、Repository、Builder、DTO/DAO 分層、AutoMapper、反射與 LINQ 全部放進同一個專案。分層後各畫面確實比較好擴充，例如新增圖表只要加一個 Builder；但重讀時也看到不少「能跑但脆弱」的地方：寫死的路徑、外部 DLL、用路徑當識別、複製貼上的篩選邏輯。這些都是下一版要優先整理的。
